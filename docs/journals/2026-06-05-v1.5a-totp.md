# 2026-06-05 - v1.5a: TOTP generator

Shipped the first half of v1.5: a built-in TOTP 2FA code generator for Login
items. Brainstorm -> plan -> cook -> commit on `origin/dev`.

## What
- `lib/ui/totp.ts` (otpauth): `parseTotp` accepts a bare base32 secret OR a full
  `otpauth://` URI (the URI path preserves non-default period/digits/algorithm;
  bare secret assumes 6 digits / 30s / SHA1). `currentCode` returns the code +
  seconds remaining. Invalid input returns null (never throws into the UI).
- `components/totp-field.tsx`: masked input + reveal + a live preview that
  validates the secret as you type.
- `components/totp-display.tsx`: drawer shows a rotating code + an SVG countdown
  ring + copy (reuses the drawer's clipboard auto-clear).
- Wired via a new `'totp'` FieldKind on the login `totp_secret` field.

## Why it stayed simple
- **No schema/RLS/CSP change.** `totp_secret` already existed in the login schema
  (encrypted inside `encrypted_data`); `otpauth` is pure JS (no network, no WASM),
  so the strict CSP and the zero-knowledge model are untouched. The code is
  computed client-side; the seed never leaves encrypted.
- Stored the raw user input (secret or URI) and parsed at display time, instead
  of normalizing on input - one source of truth, preserves URI params, KISS.

## Trade-off noted
Keeping the TOTP seed in the same vault as the password makes that account
single-factor if the vault is compromised (the same trade-off Bitwarden/1Password
accept). Documented for the user; not a blocker.

## Verification
`tsc` clean, `guard` clean (TOTP files are UI/util, no crypto/vault import),
`build` passes (267 kB, +11 kB from otpauth). No external request, no CSP change.
