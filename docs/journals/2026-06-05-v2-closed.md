# 2026-06-05 - v2 closed (nonce-CSP dropped)

Closing the v2 milestone. Shipped: **v2a** password health check, **v2b** PWA
packaging. The third candidate, **nonce-based CSP**, is intentionally DROPPED.

## Decision: do NOT pursue nonce-based CSP
- **Goal it would serve:** remove `script-src 'unsafe-inline'` to harden against an
  injected inline script reading the in-RAM DEK.
- **Why dropped:**
  - High effort vs the app's architecture: nonces require per-request rendering,
    which conflicts with this app's static prerendering (the pages are static `○`).
    Adopting nonces would force dynamic rendering (losing the static/perf benefit)
    or not work cleanly.
  - Low marginal value for a self-hosted personal vault: the supply-chain residual
    is already mitigated by pinned/minimal deps, self-hosting, and now the PWA
    service worker (precaches the build, pinning code locally instead of
    re-fetching each load) - which addresses the same threat more practically.
- **Outcome:** `'unsafe-inline'` for `script-src` is an ACCEPTED residual. Recorded
  in `docs/security-model.md` and the `next.config.ts` CSP comment.
